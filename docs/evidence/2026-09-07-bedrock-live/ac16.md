# AC16 證據：掃描件視覺讀取（部分驗證——無 Bedrock 憑證）

## ⏸ 未驗（需 Bedrock）

AC16 真正要驗的是「模型能不能看懂掃描件圖片內容」——這台機器沒有 AWS 憑證、
Bedrock 帳號仍在驗證中，`RUN_MODE=bedrock` 起不來，所以**看得懂看不懂**這件事本次
沒有驗到。以下三件事是在無模型的前提下，這條路徑能驗到的最後一步：卷證確實會被
分流成「送模型視覺讀」的類別，而不是被文字抽取層誤判成有文字層可讀。

## 已驗的三件事

### 1. 產生的樣本 PDF 確實沒有文字層

```bash
uv run --with pillow -- python3 scripts/make_scanned_pdf.py
# -> /tmp/synthetic-scan.pdf
pdftotext /tmp/synthetic-scan.pdf - | wc -c
```

**輸出：`2`**（2 頁 PDF，`pdftotext` 只吐出 2 個換頁字元 `\x0c\x0c`，沒有任何文字內容）。
來源是 `backend/data/synthetic/synthetic-ordinary-01.json` 的 `documents[]`（2 份卷證：
訴願書、原處分裁處書），逐份用 Pillow 排版成整頁點陣圖再存成 PDF，圖片裡的文字看得見，
但 PDF 格式本身沒有文字層可抽。

### 2. 掃描件 PDF 走得到上傳與路由（fixture 服務，port 8123）

```bash
uv run --with fastapi --with "uvicorn[standard]" --with pydantic --with python-multipart -- \
  python -m uvicorn backend.api.app:app --port 8123 &
curl -F "files=@/tmp/synthetic-scan.pdf" http://127.0.0.1:8123/api/cases
```

**上傳：`201`**，回傳 `case_id: upload-877485fb5d6c`（案號僅供本次驗證，不是真實案件）。

```bash
curl -X POST http://127.0.0.1:8123/api/cases/upload-877485fb5d6c/runs
```

**跑 runs：`400`**，body：

```json
{"detail": "上傳案件沒有可重播的 fixture，只能在 RUN_MODE=bedrock 執行；fixture 模式請選 synthetic- 案例。"}
```

這證明掃描件 PDF 可以正常走完上傳與案件建立，卡住的點正是「fixture 模式不跑上傳案」
這個既有機制（`backend/api/graph.py`），不是掃描件本身把管線弄壞——上傳/路由機制正確，
只差 Bedrock 模型本身能不能看懂圖片內容這一步。

### 3. `route_documents()` 把該 PDF 判成 `pdf_visual`

```python
from backend.intake.documents import route_documents
from backend.config.settings import OUTPUT_DIR
docs = route_documents(OUTPUT_DIR / "uploads" / "upload-877485fb5d6c")
```

**輸出：**

```
n= synthetic-scan.pdf | kind= pdf_visual | cjk_ratio= 0.0 | notes= ['中文比例 0.0 < 0.6，改以視覺讀取']
```

`kind == "pdf_visual"`、`cjk_ratio == 0.0`（低於 `CJK_RATIO_THRESHOLD = 0.60`），
`notes` 也如實標出「改以視覺讀取」的判斷理由。這是 AC16 在無模型情況下能驗的最後
一步：分流層正確判斷這份卷證需要送模型視覺讀取，而不是被文字抽取層誤判成有文字層可讀。

## 開通 Bedrock 後的重跑指令

Step 1（樣本已在本次產出，`/tmp/synthetic-scan.pdf`，不必重做，除非要換一批合成測資）：

```bash
uv run --with pillow -- python3 scripts/make_scanned_pdf.py
pdftotext /tmp/synthetic-scan.pdf - | wc -c     # 期望仍接近 0：沒有文字層
```

Step 2（上傳並跑 live，port 依實際服務調整——本例沿用 8123；`.env` 內含 AWS 憑證與
model id，不進 git）：

```bash
set -a; . ./.env; set +a
uv run --with fastapi --with "uvicorn[standard]" --with pydantic --with python-multipart \
       --with strands-agents --with boto3 -- \
  python -m uvicorn backend.api.app:app --port 8123 &
sleep 3

CID=$(curl -s -F "files=@/tmp/synthetic-scan.pdf" http://127.0.0.1:8123/api/cases \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['case_id'])")
R=$(curl -s -X POST http://127.0.0.1:8123/api/cases/$CID/runs)
RID=$(echo "$R" | python3 -c "import sys,json;print(json.load(sys.stdin)['run_id'])")
until curl -s -o /tmp/ac16.json -w "%{http_code}" http://127.0.0.1:8123/api/runs/$RID | grep -qv 409; do sleep 3; done
python3 -c "
import json; p = json.load(open('/tmp/ac16.json'))
print('route:', p['run_meta'].get('degraded'), '| type:', p['intake'].get('type'), '| d3:', p['intake'].get('d3'))
print([l for l in p['agents'] if l.get('k') == 'clerk'])"

kill %1
```

期望：clerk 敘述含「視覺讀取」；`intake.type` 與 `d3` 抽得出（AC16 真正通過的樣子）。
抽不出就如實記錄——這是手寫／掃描能力的量測，不是失敗。
