# AC11 證據：模型 id 設成不存在值 → 502，且回應不夾 fixture 草稿

- **來源**：`.superpowers/sdd/2026-09-07-bedrock-live-nodes/task-7a-report.md` §3（Step 4）
- **日期**：2026-09-07（Task 7a 手動驗證，commit `5902593`）
- **驗的是什麼**：`RUN_MODE=bedrock` 但模型 id／憑證都是假的，第一個節點就該炸；
  服務必須把失敗照實回成 502＋失敗節點＋原始錯誤，**不得拿 fixture 草稿頂上去**
  （CONSTITUTION §1 分層誠實）。
- **為什麼是摘錄不是本次重跑**：本機沒有 AWS 憑證、Bedrock 帳號仍在驗證中，
  無法起 bedrock 模式服務；Task 7a 當時以「假設定＋裝了 strands-agents／boto3」
  的方式跑出這段輸出，正好就是 AC11 要的形狀。

## 原始輸出（摘錄）

服務啟動（模型 id 一律填 `x`，即不存在的值；此處不寫任何真實 model id／帳號 ID）：

```
RUN_MODE=bedrock AWS_REGION=x BEDROCK_MODEL_ID_EXTRACT=x BEDROCK_MODEL_ID_DRAFT=x \
uv run ... --with strands-agents --with boto3 -- python -m uvicorn backend.api.app:app --port 8123
```

```
--- B) POST runs（期望 202 + run_id）
{"run_id":"run-synthetic-ordinary-01-30507841682f","status":"running",
 "result_url":"/api/runs/run-synthetic-ordinary-01-30507841682f"}
202
--- C) 立刻 GET（期望 409 running）
{"run_id":"run-synthetic-ordinary-01-30507841682f","status":"running"}
409
--- D) 等 25 秒後 GET（期望 502 + node/error）
{"run_id":"run-synthetic-ordinary-01-30507841682f","status":"failed","node":"n1",
 "error":"LLMError: 模型呼叫失敗（重試 3 次）：NoCredentialsError: Unable to locate credentials"}
502
--- D2) 502 body 的欄位
keys= ['error', 'node', 'run_id', 'status']    ← 沒有任何 fixture 草稿欄位 ✅（AC11 形狀）
```

## 判讀

| 要件 | 結果 |
|---|---|
| 失敗回 502（不是 200 帶空結果） | ✅ D 項 |
| 標明失敗節點 `node:"n1"` | ✅ D 項 |
| 帶原始錯誤字串（不包成「系統忙碌中」） | ✅ D 項的 `LLMError: …NoCredentialsError` |
| body 不含 fixture 草稿內容 | ✅ D2 項：只有 `error／node／run_id／status` 四鍵 |

## 待 Bedrock 開通後要補的

上面的失敗原因是 `NoCredentialsError`（連憑證都沒有）。Bedrock 開通後應再跑一次
**憑證正常、只有 model id 填成不存在值**的版本，讓錯誤變成模型端的
`ValidationException`／`ResourceNotFoundException`，證明失敗是「模型 id 不存在」
而不是「這台機器上不了雲」。指令與斷言同上，只差把 `AWS_*` 換成真憑證、
`BEDROCK_MODEL_ID_EXTRACT` 保持不存在值。
