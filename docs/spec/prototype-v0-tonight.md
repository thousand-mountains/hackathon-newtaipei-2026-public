> 今晚團隊討論用：**有畫面、有可以直接動手玩的功能**，一個晚上（~4 小時）做得完。

## 形態

```
prototype/
├── app.py            FastAPI 單檔（uv run app.py 就起）
│     /api/deadline    期間計算（真功能）
│     /api/citecheck   引用檢查（真功能）
│     /api/fixtures/…  草稿情境（罐頭資料）
├── engine/deadline.py 期間引擎（純 Python，比賽重用）
├── data/
│   ├── laws-snapshot.json    11 部法規條號清單＋修法對照（15-2→22 內建）
│   └── fixtures/*.json       三個 demo 情境（synthetic- 前綴）
└── static/index.html  單頁三分頁（CDN Vue，不開 Vite 專案）
```

**今晚不碰**：AWS／Bedrock／S3／KB、真 LLM 抽取、向量檢索、資料庫、部署。全部本機。

## 三個分頁

### ① 期間計算器（真功能，可直接用）
輸入：送達方式（本人簽收/寄存/公示）、送達日、提起日、是否在途。
輸出：期滿日＋**逐步算式卡**（每步一行：規則、法條、中間值）＋逾期判定。
知悉時/回復原狀/80 條 → 黃色 caveat 卡「此情境需人工判斷」，不硬算。
> 驗收：資料集兩份已分析的 77(2) 案（114年/03 本人簽收、113年/03 寄存＋週六順延）輸入實際日期，結果與決定書一致。

### ② 引用檢查器（真功能，可直接用）
貼一段決定書/草稿文字 → regex 抓法條與判解字號 → 對照 `laws-snapshot.json`：
✓ 有據 ｜ ⚠ 已修正（洗防法 15-2 → 顯示「已改列第 22 條（112/6/14）」）｜ ✗ 查無（紅色）。
> 驗收：貼入 `114年/15` 決定書理由段原文全綠；貼入含假字號「最高行 110 判 9999」的段落被攔。

### ③ 草稿工作台（畫面 demo，fixture 驅動）
三情境切換（罐頭 JSON，不呼叫 LLM）：
- A 逾期案：草稿＋期間算式卡內嵌（綠）
- B 利害關係案：草稿每句標判解出處（金，hover 顯示）
- C 先合後破案：事實欄＋理由骨架照出，**結論段紅區＋判斷交接卡**（安全草稿）
頁首常駐「⚠ 合成測資」badge。
> 驗收：三情境一鍵切換；紅/金/綠三級在投影下一眼可辨。
