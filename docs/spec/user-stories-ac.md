# User Stories & Acceptance Criteria（2026-08-22）

> 標記：✅v0 已驗收（附證據）｜🔵30h 競賽版｜每個 Epic 對位一個亮點。

## Epic 1｜可驗算的期間引擎 —— 亮點①「算式攤開」

### US-1 期間計算與算式卡 ✅
**作為**陳專員，**我要**輸入送達方式與日期就得到期滿日與逐步算式，**才能**驗算它、而不是被迫相信它。

- **AC-1.1** Given 寄存送達 113/6/13、When 按計算、Then 顯示期滿日 **113/7/15**，且算式含「寄存之日生效（行程法74）→次日起算（訴願法14I）→第30日 113/7/13→逢週六順延（民法122）」四步以上，**每步附法條**。
  ▸ 證據：test-vectors `hist-113-03`、pytest 綠、頁面截圖
- **AC-1.2** Given 任一輸入、When 重算 100 次、Then 結果完全相同（零 LLM、deterministic）。
  ▸ 證據：引擎為純函式；JS/Python parity 15/15
- **AC-1.3** Given 提起日恰為期滿日當天、Then 判「未逾期」（`ontime-exact` 向量）。

### US-2 歷史案全復現 ✅
**作為**評審／科長，**我要**看到引擎對真實歷史案算出與決定書一致的結果，**才能**相信它不是 demo 魔術。

- **AC-2.1** 資料集已分析之 77(2) 歷史案（114年/03 本人簽收、113年/03 寄存＋順延）輸入實際日期，期滿日與決定書原文**逐字一致**。▸ 證據：pytest hist-* 向量
- **AC-2.2** 15 個測試向量（含跨年、閏二月、在途加計後落週末、期滿當日提起）全綠。▸ 證據：pytest 4 passed＋頁面自測 badge 15/15

### US-3 不裝懂 ✅
**作為**陳專員，**我要**系統在它不該自動判定的地方明講，**才不會**被它害到。

- **AC-3.1** Given 選「公示送達」、Then **不輸出期滿日**，只輸出「請人工確認生效日」的說明。
- **AC-3.2** Given 任何逾期結果、Then caveat 必含「訴願法 80 職權撤銷」與「訴願法 15 回復原狀」兩條——**逾期≠案件終結**。
- **AC-3.3** 「知悉時起算（14 II）」「國定假日」一律以 caveat 呈現，不混入自動計算。

## Epic 2｜反幻覺引用守門 —— 亮點③「查無此號就攔」

### US-4 假字號攔截 ✅
**作為**科長，**我要**送到我桌上的草稿裡每個判解字號都被驗過，**才不會**簽到一份引用幽靈判例的決定書。

- **AC-4.1** Given 段落含「最高行政法院110年度判字第9999號」、When 檢查、Then 該引用標 **✗ 庫內查無** 並註明「送出前必須人工查證」。▸ 證據：`#t2-fake` dump-dom
- **AC-4.2** Given 114年/15 決定書理由段**原文**、Then 全部引用標 ✓ 在庫、**零誤攔**。▸ 證據：`#t2-real`「5 在庫、0 攔下」
- **AC-4.3** 30h 版：✗ 狀態**阻擋送出**（不只警告）。🔵

### US-5 修法對照 ✅
**作為**陳專員，**我要**引用到已改號的條文時被提醒，**才不會**引用三年前的條號。

- **AC-5.1** Given 文字含「洗錢防制法第15條之2」、Then 標 **⚠ 已修正**＋「已改列第 22 條（2023-06-14）」。（此修法案例為資料集內建，非假想）
- **AC-5.2** Given「噪音管制法第55條」、Then 標 ✗ 查無此條＋「該法最大條號 37」。（條號範圍抽自賽方法規 PDF，非人工輸入）

### US-6 誠實邊界 ✅
- **AC-6.1** 檢查結果頁常駐聲明：「在庫」僅代表存在於離線快照（含快照日期）；「庫外」≠錯誤＝需人工查證。

## Epic 3｜安全草稿 —— 亮點②「知道自己不知道」

### US-7 逐句出處 ✅(fixture)→🔵(真生成)
**作為**科長，**我要**草稿每一句都能點開看依據，**才能**快速覆核而不是逐句重查。

- **AC-7.1** B 型草稿每個法律主張句附引用 chip，hover 顯示驗證狀態與說明。
- **AC-7.2** 🔵 真生成版：無引用之法律主張句**不得出現**在理由段（qa-legal 抽查）。

### US-8 高風險結構封鎖 ✅(fixture)→🔵(偵測)
**作為**陳專員，**我要**系統在「先合後破」這種最容易寫壞的結構上停手，**把判斷還給我**，**才敢**在真案上用它。

- **AC-8.1** Given C 型案（時效疑義）、Then 事實欄與理由骨架**照樣產出**，唯結論段以紅區佔位——「不生成」只限結論，不是罷工（回應命題功能(4)）。
- **AC-8.2** 紅區附**判斷交接卡**：至少 3 個具體問題＋偵測訊號清單＋依據出處（114年/19、113年/20）。
- **AC-8.3** 🔵 對抗餵食：把 114年/19、113年/20 兩份已知 C 型案丟入，系統**生成了結論段＝P0**，當日修復否則砍功能。（qa-legal 執行，uncertain→NO）

### US-9 合成測資誠信 ✅
- **AC-9.1** 頁首常駐「⚠ 合成測資 SYNTHETIC」badge；demo 腳本 0:25 前完成口頭聲明；fixture 標明結構參考來源。

## Epic 4｜流程整合（30h 競賽版）🔵

### US-10 抽取與降級
**作為**陳專員，**我要**抽不準時系統自動轉手動表單，**而不是**硬塞一個猜的值給我改。

- **AC-10.1** 5 份合成訴願書（1 份仿 113年/03 故意寫錯機關字號）抽取關鍵欄位 ≥4 份全對。
- **AC-10.2** 髒測資**必須**觸發降級或人工確認，silent 錯值＝P0。

### US-11 相似案例證據面板
- **AC-11.1** 回前 3 相似案＋逐案「同/異」欄位；**全文不得出現**「應比照」「違反平等原則」等結論性措辭（文案審查）。

### US-12 Demo 可靠性 ✅
- **AC-12.1** 單檔零外部資源，file:// 斷網直開，自測 badge 15/15。
- **AC-12.2** hash 頁序（#t1-hist／#t2-real／#t2-fake／#t3-c）一鍵直達三情境。
