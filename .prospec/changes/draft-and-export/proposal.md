# draft-and-export

生成草稿的三前置條件擋門（現在第三條沒擋、失敗的樣子很像成功）、既有逐句引註能力接進 chat 工具回傳、匯出 pdf／docx 可續編可送簽。

---

## Background

**三前置條件（三個都要成立才生）：** 有卷證檔案、已解析卷證（有一次 `state >= SCREENED` 的 run）、有相關法規與相關案例。前兩條有前端或後端擋，**第三條後端目前沒有擋，而且失敗的樣子很像成功**：`n5_draft.py:138-142` 顯示上游檢索全空時草稿照樣生得出來，只是白名單是空集合，模型引的每個編號都會被清掉標 `unsupported`，N6 判紅——後端把原因寫進 log，但畫面上看不出原因出在上游。要求工具層在第三條不成立時回 `status:"failed"` + `note:"還沒有查過法規與相似案例"`，不生一份全紅的草稿（`docs/handoff/2026-09-12-frontend-contract-v2.md:495-511`）。

**草稿真值：** `cite_count` 要從 payload 實際數出，**不沿用設計稿寫死的「14 處」**（`docs/handoff/2026-09-12-frontend-contract-v2.md:487`）。

**匯出維持 pdf／docx（2026-09-12 23:50 Ci 拍板，覆蓋降級討論）：** 承辦人拿到的必須是能直接送簽或續行編修的格式，`.md` 交不出去（`docs/handoff/2026-09-12-frontend-contract-v2.md:191-206`）。兩個實作要點：

1. **中文字型要進容器**——沒有 CJK 字型 PDF 會整片豆腐字，且**不會報錯**。2026-09-12 才把 build context 從 905MB 壓到 4.8MB（commit `279169b`），加完字型要重量一次。
2. **`.docx` 要能續編**——用 `python-docx` 直接組段落，不走「HTML 轉檔」那條路（轉出來的結構很難再編輯）。

建議 `docx` 先做（起步較單純、也是承辦人真正要的「可續編」），`pdf` 若時間不夠可暫時用瀏覽器列印頂著，但**契約不退**（`?format=pdf` 仍要能用）。

## User Stories

### US-C1: 缺前置就不生草稿 [P0]

**作為**陳專員，**我要**系統在依據不足時拒絕生草稿，**才不會**拿到一份看起來完整、其實通篇沒有出處的東西。

- **C1.1** Given 沒有卷證、When 生成草稿、Then `status:"failed"` + `note` 說明缺什麼。
- **C1.2** Given 有卷證但沒解析過、Then `status:"failed"`，**後端不得自己先偷跑 n1**（那會讓使用者以為草稿憑空生出來）。
- **C1.3** Given 已解析但 `laws` 或 `cases` 為空、Then `status:"failed"`。**這條現在是紅的**——目前草稿照樣生得出來，只是每句引用被清空標 `unsupported`，**失敗的樣子很像成功**。
- **C1.4** 前端三個條件都有對應的 disable 狀態與說明文字。

**驗**：三種缺件情境各實跑一次，看回傳與畫面

### US-C2: 逐句帶引註的草稿 [大致已有]

**作為**科長，**我要**草稿的每一句都指得出依據，**才能**逐句覆核而不是整份重寫。

- **C2.1** `sections[].blocks[].cites` 的每個 id 都能在本案 `laws[]` ∪ `cases[]` 找到。
- **C2.2** `cite_count` 等於實際 cite 數，**不是**寫死的 14。
- **C2.3** 模型引了白名單外的編號 → 被清掉並標 `unsupported`，N6 判紅。
- **C2.4** C 型案（`requires_human_conclusion`）的 `conclusion` 槽位**根本不進 slots 陣列**——欄位不存在，不是叫模型別寫。

**驗**：既有 `pytest` 已涵蓋大部分；新增的是把它接進 chat 工具回傳

### US-C3: 匯出可送簽／可續編的檔 [P1]

**作為**陳專員，**我要**把草稿存成 Word 繼續改、或存成 PDF 送簽，**才能**接回我原本的公文流程。

- **C3.1** `?format=docx` 下載的檔在 Word 開得起來，**段落可編輯**（用 `python-docx` 組，不是 HTML 轉檔）。
- **C3.2** `?format=pdf` 的中文**不是豆腐字**。**這條要特別驗**——沒有 CJK 字型時它不會報錯，跑起來像成功。
- **C3.3** 引註跟著出去（轉成註腳或行內標註），**不得只匯出白文**。
- **C3.4** 加完字型後重量 build context，與 4.8MB 的基準比較並記錄。

**驗**：真的下載開來看；`docker build` 前後量 context

## 不做什麼

- 不做 pdf／docx 以外的匯出格式（`.md` 交不出去）。
- pdf 若時間不夠可用瀏覽器列印頂著，但不得取消 `?format=pdf` 這個選項——契約不退。
- 不改 N6 判定邏輯本身（沿用既有 `backend/gate/lamps.py`），本 change 只確保草稿生成前置條件與匯出格式。
- 不處理草稿內容本身的品質（措辭、法律論理），只管引註可驗與匯出可用。
